# Kimodo source review

Reviewed source: [`nv-tlabs/kimodo` at `e1c219c99b4b94ba48be1fb6a1cbc64ecee4c954`](https://github.com/nv-tlabs/kimodo/tree/e1c219c99b4b94ba48be1fb6a1cbc64ecee4c954).

This review maps integration surfaces and constraints. Reading source establishes implementation behavior; it does not verify downloaded model quality or reproduce the research benchmark.

## Subsystem map

| Source area | Responsibility | Integration consequence |
| --- | --- | --- |
| `kimodo/model` | Registry, checkpoint loading, LLM2Vec encoder, diffusion, guidance, two-stage denoiser, TMR | Use explicit generation model identifiers; TMR is an evaluator. |
| `kimodo/motion_rep` | Features, normalization, smooth-root and raw-hips representations, contacts | Preserve representation metadata and coordinate conventions. |
| `kimodo/skeleton` | SOMA, G1, SMPL-X, forward kinematics, hierarchy conversion | Validate joint layout rather than assuming every humanoid rig matches. |
| `kimodo/constraints.py` | Root, full-body, and end-effector constraints | Validate frame bounds, shapes, units, and joint names before inference. |
| `kimodo/postprocess.py`, `MotionCorrection` | Foot cleanup and native constrained motion correction | Diagnose the native extension separately from the model packages. |
| `kimodo/exports` | NPZ, SOMA BVH, G1 CSV, AMASS conversion and resampling | Select exports by skeleton; use upstream conversion helpers. |
| `kimodo/demo`, `kimodo/viz` | Timeline authoring, scene/skin visualization, examples, queues | Useful reference for complete authoring flows; not a generic mesh generator. |
| `kimodo/scripts` | Generation, conversion, encoder service, helper commands | Process boundary for the bridge. |

## Model catalog

Nine generation checkpoints are registered: SOMA-RP v1/v1.1/v1.2, SOMA-RP-ArdyRep v1.2, SOMA-SEED v1/v1.1, G1-RP v1, G1-SEED v1, and SMPLX-RP v1. The `kimodo-soma-rp` alias resolves to SOMA-RP v1.2 at this revision. TMR-SOMA-RP v1 is separate and evaluates motion/text correspondence.

The standard SOMA model uses a smoothed root. The ArdyRep variant uses raw hips as root. Root metrics across these representations measure different targets and should not be directly compared.

## Compatibility observations

- SOMA predicts 30 joints internally and exports a 77-joint public skeleton. The bundled SOMA examples still contain 30 joints.
- All 16 bundled example NPZ files contain `posed_joints`, `global_rot_mats`, and `foot_contacts`; they do not include every field written by current generation. Import must reconstruct missing fields when necessary.
- There are 16 example metadata files and 10 constraint files covering text, prompt sequences, root paths, waypoints, poses, end-effectors, mixtures, styles, terrain, and objects.
- The CLI page has an outdated v1 default in its argument list, and benchmark instructions still mention v1.1 in one paragraph. The registry and October 2026 changelog resolve the actual v1.2 default.
- Package metadata advertises Python 3.8, while modern annotations and tested environment guidance call for Python 3.10 or newer.
- The Docker dependency lock targets Linux. It is not a Windows lockfile.

## Limits that matter to an assistant

A prompt segment is at most 10 seconds. Sequential generation produces longer clips by using preceding frames as transition constraints. Prefer fewer than 20 constrained frames per non-root constraint type; dense root paths are the exception. Constraints use meters, Y-up, and +Z-forward, with zero-based frame indices. End-effector JSON stores a full pose from which the target joints are derived, rather than only a hand xyz coordinate.

Foot-contact conditioning exists in training but is not exposed by the documented Python/UI interface. Post-processing improves contact and constraint adherence; upstream documents weaker results for G1. SMPL-X may exhibit substantial retargeting artifacts. Finger articulation is not independently generated by the reduced SOMA model.

The project does not provide arbitrary mesh generation, automatic skinning of user meshes, general custom-rig retargeting, or native FBX/GLB export. BVH is the supported SOMA interchange format; arbitrary BVH hierarchies are not automatically accepted on import.

## Benchmark interpretation

The public suite has 22,474 test cases. Building it requires the separately licensed BONES-SEED source data and roughly 26 GB for the constructed suite. Source review does not constitute a benchmark run.

Generation uses the first seed and denoising-step value in a batch for the entire batch. Use batch size one for exact per-case seeding. Match model version, embedding precision, post-processing, and TF32 settings before comparing results. SOMA-RP v1.1 has disclosed test-set overlap; v1.2 corrects its training splits.

Metrics cover foot skating, contact consistency, positional constraints, and TMR alignment. End-effector rotation error is not implemented in the summary. FID requires more than one sample and cannot serve as a meaningful single-animation quality score. Missing metrics should be reported unavailable.
